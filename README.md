> 私人存档仓库（Private）。本仓库仅作备份，不对外开源。

## 软件简介

Windows 文件夹工作台：用标签页托管系统资源管理器视图，支持多标签、搜索五列详情、目录级查看/排序记忆、外部「打开所在文件夹」归并，以及关闭窗口后的轻量常驻接收。

- **完整版**：内置 .NET，解压即跑（体积较大）
- **精简版**：约 1 MB，需本机安装 [.NET 10 Windows Desktop Runtime x64](https://dotnet.microsoft.com/download/dotnet/10.0)
- 系统要求：Windows 10/11 x64

# 文件夹工作台 2.4.33

本版是 UI-1/2/3 界面细化：竖标签选中态由整块变色改为左侧短指示条，设置窗左栏改为圆角轻选中，正文文字对比度统一，关闭行为选项左对齐成组。

- **竖标签选中淡化**：激活标签保留 `TabActive` 轻底，左侧强调条缩为 2px、上下各留 8px、透明度 0.55，不再用整根蓝条抢走视觉重心。
- **设置左栏圆角选中**：左导航改为自绘 `SettingsNavItem`（圆角 8、悬停 `HoverBrush`、选中 `AccentSoftBrush` + Medium 字重），去掉系统硬选中框。
- **正文对比度**：设置项标签、复选框文字统一使用 `Ui.Ink`（正文前景），不再继承偏淡的默认前景。
- **关窗行为左对齐**：完全退出 / 轻量常驻两项改成左对齐分段选项行（1px 轻边框，选中为 `AccentSoft` 底 + SemiBold），第三项「保存会话并转后台接收」是**普通动作钮**，不进选中态，避免被误读成第三档单选。
- 详见 `修改记录.md` 的"2.4.31"段。禁区不变：未改 Shell 文件列表、菜单、PIDL 身份与 RowBands。

# 文件夹工作台 2.4.22

本版把搜索结果从单行摘要改成**五列详细信息视图**，用于区分同名文件；并把搜索的取消、完成与迟到回调变成可观测、可断言的结构化状态。

- **五列**：名称 / 所在文件夹 / 修改日期 / 类型 / 大小。所在文件夹直接可见（这是区分同名文件的关键），单击列头可按原始值排序，列宽可拖动并记住。名称列保留原图标。
- **状态**：搜索有明确的进行中/已完成/取消/截断/失败状态，取消后界面不会停留在"正在搜索…"。
- **诊断（默认关闭）**：`--search-diagnostics` 开启事件与状态快照；`--search-delay-ms=2000` 用于测试时建立稳定的在途窗口，仅在诊断开启时生效，上限 2000ms。
- 详见 `修改记录.md` 的"2.4.22"段（含 CLI、事件 schema、状态文件身份与未验证边界）。
本版新增“关闭窗口后的行为”设置，两种退出方式：

- **轻量常驻接收**（默认推荐用于天天用外部“打开所在文件夹”）：关闭工作台界面即真正结束界面进程，由独立的轻量接收器进程继续接收外部打开。接收器只占消息循环、一个事件钩子和托盘图标（实测约45MB工作集、11MB私有内存），不加载WPF界面。外部请求到来时它先把系统窗口隐藏，再拉起工作台界面接收并归并；若界面未在期限内确认，会恢复系统窗口，不会留下看不见的窗口。
- **完全退出**：关闭窗口即结束全部工作台进程，不再接收外部打开。

托盘与设置菜单都提供“打开工作台”“退出接收器（完全退出）”，接收器可在系统托盘看到并随时停止。

**边界未变：完全退出后，明确调用 explorer.exe /select 或 SHOpenFolderAndSelectItems 的第三方请求不会唤起工作台；默认文件夹关联只覆盖走该关联的打开入口。** 需要在界面关闭后仍接收，请选择轻量常驻并保留托盘接收器。

本版还包含 IShellWindows 注册研究：实测系统会等待已登记的“待打开 Shell 窗口”，说明存在比窗口更早的接管路径；但完成交付需要原生 Shell 窗口对象，托管对象无法直接注册，因此本版不启用该路径，详见 docs/2.4.17-IShellWindows研究.md。

2.4.16 的每目录查看/排序/分组保存、各布局选择高亮、关闭前台后的进程内后台接收均保留。

完整版内置 .NET；精简版需要 .NET 10 Windows Desktop Runtime x64。使用新版前彻底退出旧版，避免两套接收器争抢同一来源。交付目录含源码、两版单文件 EXE、实测报告与哈希清单。

# 文件夹工作台 2.4.16

本版按目录保存查看模式、图标尺寸、排序列与方向、分组依据与方向；离开返回和重新构造标签后恢复。设置存于用户状态目录的 folder-views.json，独立于旧会话格式。目录状态只在变化时去抖落盘，离开、关闭或退出前提交。

选择高亮扩展至图标、平铺和列表，限定在文件单元格内；详细信息和内容视图保留行着色。选中着色继续使用原生PIDL身份映射，重点标记和原生菜单保持；移除上轮未经证实的空身份映射提前返回。

启用自动归并时，关闭最后一个工作台窗口会保存会话、销毁前台Shell视图并保留托盘接收器。设置及托盘提供“保存会话并转后台接收”以及“彻底退出（停止外部接收）”。外部请求到来才重新构建前台页面。

**边界：真正彻底结束全部工作台进程后，明确调用 explorer.exe /select 或 SHOpenFolderAndSelectItems 的第三方请求无法由本应用接收；默认文件夹关联只覆盖走该关联的打开入口。需要持续接收时使用关闭窗口或转后台。新版不把后台常驻描述为完全退出。**

完整版内置.NET；精简版需要.NET 10 Windows Desktop Runtime x64。使用新版前彻底退出旧版，防止接收器抢同一来源。交付目录同时保留源码、两版单文件EXE、实测报告与哈希清单。验收结论见本轮报告，以下仅为历史版本记录。

# 文件夹工作台 2.4.11

新增外部软件“打开文件所在文件夹”定位：工作台弹出，复用已有目录标签，选中目标并滚动至可见位置。等待目录加载和布局稳定后按 PIDL 确认目标，两次测量实际可视区域；多个远隔目标保留多选并优先显示首个目标。用户开始操作、导航或切换标签后，旧定位请求停止。

保持工作台运行并启用“设置与工具 → 外部窗口归并”，即可接收其他软件通过 Explorer /select 或 SHOpenFolderAndSelectItems 发起的请求。新建单标签来源确认定位后归并关闭；已有窗口或多标签来源保留，避免影响其原有标签。工作台关闭或归并暂停时仍由 Windows 处理。

也可由其他软件直接调用 `FolderWorkbench.exe /select,"完整路径"` 或 `FolderWorkbench.exe --select "完整路径"`。文件夹目标选中该文件夹，普通目录参数则进入该目录。

新增 --reveal-test 覆盖 3000 文件、分组/图标、已开标签、多选锚点、最小化恢复、连续请求和导航取消；--integration-test 实际调用 Windows 定位接口并验证已有双标签窗口的接收、保留和超时恢复。两个版本发布前分别运行完整门禁，报告与哈希随包。

继承 2.4.10 的分组选择与重点标记修复：

本版修复分组、排序和切换查看方式后，点选高亮与重点标记对应错误的问题。

- 分组视图中 UIA AutomationId 会在每组重计。行缓存改为读取 Shell 提供的当前整个视图项目编号，再与原生 PIDL / 文件路径身份对应；不按显示名称或旧行序号猜测。
- 原生菜单和工具栏切换查看方式后，同步原生模式及图标大小，重新获取单元格几何信息。图标模式的重点圆点随项目单元格定位，不使用整行左边缘。
- 排序、刷新、原生菜单命令和布局变化时，旧几何信息与身份映射一起失效。文件选择和菜单内容仍由 Windows 处理。
- 保留原生点选、多选、重命名、隔行明暗、空白双击返回、滚动缓冲、外部 Explorer 联动、同名/本地化身份标记。

## 运行

完整便携版的 FolderWorkbench.exe 可直接运行，无需安装 .NET。
精简版需要安装 .NET 10 Desktop Runtime x64。

正常启动使用原有用户数据目录 `%LOCALAPPDATA%\FolderWorkbench`。升级前退出旧版，再运行新版。书签、标签和外观设置沿用原有配置。

“设置与工具”内可启用或暂停外部窗口归并。设为默认文件管理器后，Windows 按文件夹关联打开目录的入口会直接进入工作台。第三方软件若明确调用 explorer.exe 或 SHOpenFolderAndSelectItems，仍需经过来源窗口识别和归并；不同软件和 Windows 版本的表现可能不同。

## 常用操作

- Ctrl+L 编辑地址；Alt+Left / Alt+Right 后退与前进；Alt+Up 返回上层；F5 刷新。
- Ctrl+T 新标签；Ctrl+W 关闭标签；Ctrl+Shift+T 恢复关闭标签。
- 命令栏收藏当前目录；Ctrl+F 搜索。在文件区，Ctrl+D 按原生文件删除处理，Ctrl+Shift+C 复制所选文件路径；焦点在外层时仍可使用目录收藏和地址复制。
- 文件列表空白处双击返回上层；文件项目继续使用原生右键、拖放和剪贴板操作。

## 编译与测试

需要 .NET 10 SDK，运行 `build.ps1` 生成完整便携版。项目不使用外部业务 NuGet 库；自包含打包需要 .NET 的 Windows 运行时包。

隔离测试示例（测试路径请设在可写目录）：

```powershell
.\FolderWorkbench.exe --self-test --state-dir "D:\WorkbenchTests\Native"
.\FolderWorkbench.exe --integration-test --state-dir "D:\WorkbenchTests\Integration"
.\FolderWorkbench.exe --visual-test --state-dir "D:\WorkbenchTests\Visual"
.\FolderWorkbench.exe --scroll-test --state-dir "D:\WorkbenchTests\Scroll"
.\FolderWorkbench.exe --input-test --state-dir "D:\WorkbenchTests\Input"
.\FolderWorkbench.exe --click-test --state-dir "D:\WorkbenchTests\Click"
```

原生视图测试覆盖导航、历史、选择、分屏、连续切换、刷新、错误恢复和 GDI 资源回收。归并测试会新建专用目录，打开并关闭其 Explorer 窗口，并模拟自动化线程延迟；不要把日常数据目录用作测试状态目录。测试不会设置默认文件夹关联或 Win+E。

视觉测试使用生成的渐变背景，读取实际 Shell 显示模式，采样快速滚轮与标签切换时的文件区域，并连续弹出、测量原生右键边缘。测试真实 Explorer 归并前，请暂停其他运行中的工作台实例的外部归并，避免同时接管测试窗口。

`--no-integrations --state-dir "路径"` 可用独立配置启动并关闭外部联动，也不会显示默认文件管理器接管询问。
